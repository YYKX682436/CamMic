# CamMic 0.6.0 beta 1

This is the first public test candidate. It has not been published as a GitHub Release or tagged. The successful [delivery workflow on main](https://github.com/YYKX682436/CamMic/actions/workflows/ios14-ipa.yml?query=branch%3Amain%20is%3Asuccess) records the exact source commit and generated artifact; the Mac ZIP includes that commit's full source archive.

## Highlights

- Use an iPhone as a selectable **CamMic** microphone on an Apple silicon Mac.
- Start capture on iPhone, connect USB, and let the Mac discover it automatically. USB needs no CamMic pairing code, IP address, Homebrew, or terminal command.
- Continue active capture with the iPhone locked, subject to normal iOS audio-session interruptions.
- QuickTime and other recording apps can select CamMic as their input; the Mac's speaker output is not changed.
- iOS build **4**, minimum iOS **14.0**; Mac build **6**, minimum macOS **13.0**, Apple silicon.

## Validation record

CI checks the iOS and Swift package regressions, USBMux dependencies, CoreAudio/HAL, unsigned IPA and Mac source package, plus installer upgrade, rollback/recovery, repeat-install and uninstall behavior. The workflow page above identifies the exact commit and result for the downloadable candidate.

Physical checks used an iPhone XR (`iPhone11,8`) on iOS 14.3 and an Apple silicon Mac mini on macOS 27.0.1. The exact candidate IPA identified as version 0.6.0 build 4, minimum iOS 14.0. After installing the retained 0.5.0 baseline, the candidate Mac installer completed and reported version 0.6.0 build 6, minimum macOS 13.0. With capture started on the iPhone and USB attached, the Mac connected automatically without a CamMic pairing code. QuickTime selected CamMic, recorded 20.39 seconds of real speech, and the saved recording played back clearly. Closing and reopening the CamMic window preserved the live connection. Main-window mute/unmute and stop/resume controls were clicked; stop silenced the meter and resume restored a nonzero live level. During a short locked-phone check the Mac meter continued moving. CoreAudio inventory checks found unrelated devices and plug-ins unchanged; the default Mac mini speaker output stayed selected.

Still **NOT_VERIFIED** on this exact candidate: a physical USB unplug/replug cycle, the actual menu-bar mute/unmute/stop/resume/quit clicks and post-quit forwarding-port cleanup, and the requested iPhone running-screen capture. Accordingly, no result is claimed for those checks. The successful CI lifecycle suite covers safe install, upgrade, recovery, repeat install and CamMic-only uninstall, but it does not replace those missing live UI checks. The minimum OS versions are not a claim that every device running iOS 14+ or macOS 13+ has been tested.

## Download and install

Download these three files from the matching successful workflow artifact:

1. `CamMic-iOS14-unsigned.ipa`
2. `CamMic-macOS-arm64.zip`
3. `SHA256SUMS`

On Mac, unzip the archive and run the single main installer, `CamMic-Installer.pkg`. On iPhone, install the unsigned IPA with TrollStore or your own signing method. Grant microphone access when prompted. Then start USB capture on iPhone, connect the cable, and select **CamMic** in QuickTime's input menu.

The unsigned Mac app, HAL driver, package and IPA are not Developer ID signed or notarized. The Mac app and driver have local ad-hoc signatures. If macOS blocks the installer, use Finder's per-app **Control-click → Open** flow or the CamMic-specific allowance in Privacy & Security. Do not disable system-wide security. The archive has the corresponding full source and license notices; optional repair and uninstall tools are in its optional-tools folder.

## Known limits

- CamMic currently provides a microphone only. Camera support is paused.
- iOS **14.0** and macOS **13.0** are minimum deployment versions, not device-coverage claims.
- USB automatically connects a trusted USB device but does not authenticate a particular Mac process. During active capture, another process with access to the USB forwarding path or the phone's loopback socket may obtain the temporary session key. See the [USB security boundary](../development.md#usb-session-security-boundary).
- iOS calls, Siri, and competing audio sessions can interrupt capture.
- Wi-Fi remains an advanced option and requires the existing IP address and pairing-code flow.
- The Mac release is for Apple silicon; no Intel Mac package is provided.

## License, source, update, and uninstall

CamMic's integrated application and driver distribution is GPL-3.0. Original CamMic code retains its MIT notice; bundled USBMux libraries are LGPL-2.1-or-later. The Mac archive contains the exact corresponding source archive, upstream notices, and license texts. The source is also available from the repository at the same commit as the workflow artifact.

For updates, install the new IPA over the existing iPhone app without uninstalling or clearing data, and rerun `CamMic-Installer.pkg` on Mac. To remove CamMic, use `optional-tools/uninstall-cammic.sh`; it removes only CamMic's recognized application, driver, and package receipts. Do not remove recovery backups manually after an interrupted installation.

### 已知限制

- 仅支持 Apple silicon Mac，没有 Intel 版本。
- iOS 电话、Siri 和竞争的音频会话可能中断采音。
- USB 自动发现沿用现有 USBMux 和 TLS-PSK 协议；Wi-Fi 高级连接仍需 IP 和配对码。
- USB 会话密钥在采音时通过 USB 转发的本机回环初始化通道传递。应用不验证特定 Mac 进程身份；详见[开发文档](../development.md#usb-session-security-boundary)。
